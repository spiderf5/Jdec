# M8 容器分类与多版本/截断类隔离

## 可观测形态（字节码 / 容器层面）

容器由文件头 magic 区分：`4d5a`（MZ，PE 自解压 stub 后接 zip）、`504b`  
（PK，普通 zip / jar）、或目录本身；zip 中央目录里条目名带  
`META-INF/versions/N/` 前缀的是 multi-release 备选；被截断 / 不可解码的 class  
表现为条目存在但字节长度与 class 结构不自洽。特征是文件头与中央目录层面的，  
不含容器加密或自定义格式实现代码。  

## 本工具的支持项

对输入执行 `probe`，按 magic 识别 MZ stub + zip 自解压容器、普通 PK jar 与  
目录，读出条目数与类数；`ircheck` 对不可读类**隔离**（单列 unreadable）而不是  
把整批判为失败。输入条件是文件头可读、zip 中央目录可枚举；产出是容器类型、  
条目 / 类计数与坏类隔离清单。支持项止于「分类与隔离」。  

## 已知不覆盖

- 不处理加密容器（加密 zip / 自定义打包），按其边界拒绝。  
- multi-release 条目按「同一基类的备选」排除，不把它们计成独立的新类。  
- 不修复截断 / 不可解码类，只隔离与如实报告。  
- 不把「坏类被隔离」写成「全批已通过」；整批结论需逐类相等另证（见 M2）。  

## 独立样本与可测点

| 语料 | 可测点 |
| --- | --- |
| `HMCL-3.15.2.exe` | magic `4d5a`、MZ stub + zip 自解压、条目数 / 类数 |
| `NeoRaven1.1.jar` | magic `504b`、普通 PK jar、条目数 / 类数 |
| 公开阴性对照 jar | 普通 PK、无 multi-release / 截断类、分类结果应为普通 jar |

## 独立金标准

不取 `probe` 自身输出。直接读文件**前 2 字节**判 magic（`4d5a` / `504b`），  
用 `zipfile` 独立枚举中央目录原始条目列表与条目名前缀  
（`META-INF/versions/`），独立统计条目数与类数；对照文件头判断是否目录。  
真值问题是「magic 与中央目录条目是否与工具分类一致」，不是「probe 报了什么  
类型」。  

## 负控（构造方式与预期失败）

构造 A：一个含**截断 class**（与 `src/tests/sample.jar` 同类）的 PK jar。预期  
`ircheck` 报 unreadable ≥ 1 或明确非 PASS，坏类被隔离、其余类仍各自处理，  
**不得**报「整批干净 PASS」。构造 B：一个带 `META-INF/versions/9/` 重复基类  
的 multi-release jar。预期备选条目不计成额外新类、类数按基类去重，**不得**  
虚增。构造 C：一个加密 / 非 zip 的伪装容器。预期按边界拒绝，**不得**误分类成  
普通 PK jar。三者夹逼分类与隔离门禁不恒真。  

## 与 03 阶段、独立研究线的边界

03 的隔离是 Java 级 SecurityManager 沙箱 + 进程级外层，不是用户 / 容器级 OS  
边界（`ROADMAP:223-227`）；本类的「隔离」是 class 级容错，二者同名不同义。  
加密容器还原、JNIC 自定义容器还原属 `ROADMAP:231-236` 独立研究线，永不并入  
通用恢复承诺，本清单不把它们算 1.0 默认支持项。当前语料只有 MZ stub 与 PK  
两种形态，加密容器目标数为 0，只如实报告，不记为已攻克。
