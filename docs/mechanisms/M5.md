# M5 字符串常量抽取与加密/威胁标签

## 可观测形态（字节码 / 容器层面）

常量池 `CONSTANT_Utf8` 条目是字符串真值的容器级来源；url / path /  
credential / machine-id / class-loading 等标签对应可识别的字面前缀与字符集；  
所谓「加密 blob」在形态上是高熵、base64 字符集、长度远大于普通标识符的  
字符串。但高熵 base64 串也可能是合法 FQCN、类名或资源名，单靠字符集会把  
FQCN 误标成密文。特征是常量池原始字节层面的，不含解密实现代码。  

## 本工具的支持项

对真实 jar 执行 `strings -o`，抽取常量池字符串并按 url / path / credential /  
encrypted-blob / machine-id / class-loading 分类标注，输出 TSV + JSON。修复后  
的口径：标为 `encrypted-blob` 前须通过 **base64 解码**且做 **FQCN 排除**  
（解码结果若落在合法 Java 全限定名 / 类名形态则不标密文）。输入条件是 class  
可解析、常量池可读；产出是明细 TSV 与汇总 JSON。支持项止于「抽取 + 启发式  
标注」，不等于解密。  

## 已知不覆盖

- 标签是启发式，不是解密证明；抽取不等于解密 ZKM 池。  
- **本语料上不存在 ZKM DES 字符串池**：经独立金标准核实 `NeoRaven1.1.jar`  
  常量池无 `DESKeySpec` / `DES/CBC/PKCS5Padding` / `zelix` / `$CodePool`；旧  
  「8 个 encrypted-blob / ZKM 27 enhanced DES」结论是 `probe` 关键词误报  
  （命中 AES-CBC 也用的 `javax/crypto/spec/ivparameterspec`）。修复后须以  
  base64 解码 + FQCN 排除复核，**不得**据旧结论标注加密池。  
- `pool/recover` 的解密重放不在本支持项内；不还原密钥与常量折叠引擎。  
- 不处理运行时拼接、反射生成、native 侧返回的字符串。

## 独立金标准

不取 `strings` 自身输出。用 `zipfile` 取 class 原始字节，独立解析常量池导出  
全部 `CONSTANT_Utf8` 字面量，逐条做 base64 解码并判断是否落在 FQCN / 类名  
形态；用 `javap -v` 独立核对条目数。真值问题是「被标 encrypted-blob 的字面量  
是否真的 base64 可解码且不是 FQCN」，不是「strings 打了几个标签」。  

## 负控（构造方式与预期失败）

构造 A：往常量池塞一个**看似 base64、解码后却是合法 FQCN**（某包名 / 类名  
字符串）的字面量。预期 FQCN 排除生效，该条**不得**标为 encrypted-blob；若  
误标，说明门槛不恒真。构造 B：塞一个解码后为乱码高熵字节、非 FQCN 的字面量。  
预期可被标为 encrypted-blob 候选（仍只是候选，不解密）。两者夹逼 base64 +  
FQCN 排除复核的有效性。
