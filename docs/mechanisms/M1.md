# M1 控制流去平坦化 / 常量折叠 / 不透明谓词

## 可观测形态（字节码 / 容器层面）

类文件的 `Code` 属性里出现密集的 `goto` 链（线性代码被拆成大量短基本块，  
即 goto-flood）、不可归约的 `goto`（irreducible-goto）、把常量拆进长数组再  
按索引取用（long-constant-array）、以及恒真 / 恒假分支包裹的不透明谓词。  
这些形态伴随 `StackMapTable` 帧数量与位置的异常；容器层面表现为普通 jar  
内一批 class 条目的 Code 长度分布与 vanilla 编译产物显著不同。特征是统计  
与结构层面的，不依赖任何混淆器实现代码。  

## 本工具的支持项

对「含上述形态的真实 jar」执行 `deflat`：产出可重放的指令级改写清单  
（`--rewritten`），重算 `StackMapTable`，并让全部类通过 JVM 的  
`-Xverify:all`。输入条件是 jar 可被解析、类无 `jsr/ret`；产出是改写后 jar  
与逐方法改写清单，供后续行为对拍。支持项只承诺「改写并重放后可验证加载」，  
不承诺与原文语义等价的证明。  

## 已知不覆盖

- 不还原任意自定义 VM 的调度器与虚拟指令集；这类 VM 把控制流搬进解释器，  
  字节码层已无对应的 goto 链可去平坦化。  
- `jsr` / `ret` 子程序指令明确拒绝，不进入改写管线。  
- 改写保持可验证加载，但**不证明**与原始类语义等价；等价性要靠独立行为  
  对拍（03 口径）另证。  
- 不处理被加密容器包裹、或 Code 数组被整体替换的类。

## 独立金标准

不取 `deflat` 自身输出。用 `javap -v -c` 独立导出原始与改写后类的 `Code` /  
`StackMapTable` 与 `LineNumberTable`，逐方法核对指令序列差异；用 JVM  
`-Xverify:all` 作为独立于被测命令的加载校验；用 `zipfile` 读取原始 class  
条目字节确认方法范围。真值问题是「改写清单是否与 javap 看到的真实指令  
改变量一致、且类能被独立 verifier 接受」，不是「deflat 报了改写数」。  

## 负控（构造方式与预期失败）

构造 A：一个仅含线性直落代码、无 goto-flood / 无不透明谓词的干净 class，  
放进小 jar。预期 `deflat` 改写数 = 0 或明确「无需改写」，**不得**虚构改写  
清单凑数。构造 B：一个含 `jsr/ret` 的类。预期工具明确拒绝该类（非零退出  
或在清单标 REJECTED），**不得**把它算作已改写且 verify 通过。两者用来证明  
「改写数 > 0 / verify > 0」的门禁不恒真、也不把拒绝误报成成功。  

## 与 03 阶段、独立研究线的边界

03 对同类机制的验收是 `behave` 行为对拍 0 差异 + judged union；本笔记的  
`deflat` 单命令只到「可重放改写 + 可验证加载」，证据强度**低于** 03，不沿用  
03 的达标结论。自定义 VM 还原、把解释器调度器搬回字节码属  
`ROADMAP:231-236` 独立研究线，永不并入通用恢复承诺，本清单不算 1.0 默认  
支持项。当前独立语料不含 BytecodeVM `$CodePool`，该 VM 目标数为 0，只如实  
报告 0，不记为已攻克。
