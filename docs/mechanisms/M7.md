# M7 Minecraft 元数据与 Mixin hook 识别

## 可观测形态（字节码 / 容器层面）

容器层面，MC 客户端 / mod jar 的 `version.json`、`mcmod.info`、`META-INF` 或  
Forge 元数据文件里带版本号与加载器名；Mixin 以 `mixins.<mod>.json` 配置或  
`org.spongepowered.asm.mixin` 注解形式出现，hook 目标名写在注解的原始字符串  
里。字节码层面，注解以 `RuntimeVisibleAnnotations` 属性挂在类 / 方法上，  
常量池里有目标类名 / 方法名的 `CONSTANT_Utf8`。特征是元数据文件与注解属性  
层面的，不含映射表实现或反编译片段。  

## 本工具的支持项

对真实客户端执行 `probe` + `analyze -o`：识别 MC 版本 / 加载器、Mixin 配置  
或注解 hook，并在**无映射时如实保留 hook 目标名**（不擅自改写）。输入条件  
是 jar 可解析、元数据 / 注解属性可读；产出是版本 / 加载器结论、Mixin 配置  
状态与 hook 目标名清单。支持项止于「识别与如实保留」。  

## 已知不覆盖

- 映射表（mcp / yarn / mojmap）本身外置，不随工具交付；无映射时**不解析 hook  
  目标的最终符号**。  
- 不把注解里的目标名反混淆为可读名；不重写 Mixin 配置。  
- 不识别被加密 / 自定义元数据容器包裹的版本信息。  
- 不覆盖非 `neo` 语料（M7 的独立样本仅 `NeoRaven1.1.jar`）；对普通 jar 如实报  
  「无 MC 元数据」。  

## 独立样本与可测点

| 语料 | 可测点 |
| --- | --- |
| `NeoRaven1.1.jar` | `1.8.9 / Forge` 版本 / 加载器结论、Mixin 配置或注解 hook 说明、无映射时保留的 hook 目标名 |

## 独立金标准

不取 `probe` / `analyze` 自身输出。用 `zipfile` 取出 `version.json` /  
`mcmod.info` / `mixins.*.json` 的**原始条目字节**独立读版本号与加载器；用  
`javap -v` 独立导出 `RuntimeVisibleAnnotations` 与注解里的原始目标名字符串；  
用常量池原始 UTF8 核对。真值问题是「版本 / 加载器 / hook 目标名是否与原始  
文件字节一致」，不是「probe 打了什么标签」。  

## 负控（构造方式与预期失败）

构造 A：一个不含任何 MC 元数据 / Mixin 配置的普通 jar（公开阴性对照）。预期  
工具**不得**声称 1.8.9 / Forge，也不得虚构 hook；应报「无 MC 元数据」。  
构造 B：一个 Mixin 配置里写了不存在 / 伪造的 hook 目标名、且无映射表的 jar。  
预期工具**如实保留**该目标名，不擅自解析成最终符号、不报解析成功。两者证明  
版本识别与「如实保留」不恒真、不把缺失误报成命中。  

## 与 03 阶段、独立研究线的边界

03 的隔离重放是 Java 级 SecurityManager 沙箱 + 进程级外层，不涉及 MC 元数据 /  
Mixin（`ROADMAP:223-227`）。Mixin 目标符号的最终反混淆依赖外置映射表，属按项目  
单独提供；frida→Ghidra / JNIC 容器还原属 `ROADMAP:231-236` 独立研究线，永不  
并入通用恢复承诺，本清单不把它们算 1.0 默认支持项。对当前唯一语料，识别结论  
是 1.8.9 / Forge 与注解级 hook 说明，不含映射解析。
